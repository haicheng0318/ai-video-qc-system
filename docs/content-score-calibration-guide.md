# 内容质量评分校准指南

## 评分契约

`content-score-v2` 将“模型观察”和“业务计分”分开：Qwen-Omni 只返回 12 个固定维度的 0–5 原始等级、逐项证据、风险和建议；后端再按版本化规则计算 0–100 总分与 S/A/B/C/D。模型不得自行填写总分或等级。

| 维度 | 权重 |
|---|---:|
| 前 3 秒吸引力 | 15 |
| 产品露出 | 10 |
| 卖点表达 | 15 |
| 画面质感 | 10 |
| 构图 | 5 |
| 镜头语言 | 5 |
| 节奏 | 10 |
| 字幕清晰度 | 5 |
| 口播清晰度 | 5 |
| BGM 匹配度 | 5 |
| 平台适配 | 7 |
| 用途适配 | 8 |
| 合计 | 100 |

单项含义：0 为完全缺失或明显不可用，1 为严重不达标，2 为明显有问题，3 为最低可用，4 为良好，5 为优秀且证据充分。

基础分为 `round(sum((rating / 5) * weight))`。90–100 为 S，80–89 为 A，70–79 为 B，60–69 为 C，0–59 为 D。

硬边界：任一高风险合规问题把总分封顶为 59，并强制发布建议为否；商品卡、千川投放、直播间引流视频若产品露出为 0，把总分封顶为 69，并强制发布建议为否。命中的边界及计算明细保存在 `raw_response.calculated`，便于复现和审计。

## 版本和历史结果

- 新结果保存 `scoring_version=content-score-v2` 与 Prompt 版本。
- 已有成功记录只补充 `legacy-model-score-v1` 标识，原总分、等级、维度和原始响应均不改写。
- 页面明确区分“后端规则计算”和“历史模型评分”。不同评分版本不能直接用于纵向绩效比较。
- `platform_benchmarks` 仍只服务运营/投放数据复盘，不进入内容质量评分。

## 人工校准流程

1. 选择至少 20–30 条已取得使用授权、覆盖六种视频类型和不同质量层级的视频；不要用运营/投放结果倒推内容分。
2. 两位业务评审独立按同一 12 维 rubric 打 0–5 分，并写出可定位到画面、字幕或音频的证据。
3. 两位评审的最终等级相差超过 1 级，或关键维度相差超过 2 分时，交由第三位负责人复核，不直接取平均。
4. 将人工共识等级与系统结果对照，记录等级命中率、相邻等级命中率、分数分布、各维度偏差和硬边界命中情况。
5. 只有在样本覆盖和偏差证据充分时才发布新评分版本；不得原地修改 `content-score-v2` 的含义。

当前自动化夹具是匿名合成数据，只验证公式、等级边界、硬封顶、结果离散度和“不会固定为 85”。它不能证明真实业务准确率，也不能替代上述人工校准。

## 发布门禁

- 通过 schema、评分器、服务、迁移、页面和校准夹具测试，以及全量 typecheck/build。
- 在隔离数据库验证迁移；迁移前后抽查历史记录的总分、等级与原始响应指纹不变。
- 生产发布前备份并登记候选镜像、迁移状态和回退目标。
- 首次真实评估只选择一条已批准样本，单独确认付费模型预算；结果异常时停止扩大样本，不自动连续重试。
- 灰度结果需同时检查 12 项是否齐全、证据是否与视频相符、后端重算是否一致、是否清理临时 OSS 对象。
