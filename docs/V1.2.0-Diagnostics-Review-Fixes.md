## Shared Type与实际JSON

管理员：group.inputRevision 为 `{ factClaimVersion: string | null } | null`；Run包含 modelProvider/modelName/promptVersion/schemaVersion/rubricVersion/structuredOutput，以及从input revision派生的factClaimVersion。

普通用户：JSON不含inputRevision；Run不含上述技术字段。共享类型通过 optional never 表达字段不可提供。
共用字段包含nullable complianceStatus/completedAt；分数仍允许JSON字符串、数字或null。
HTTP测试使用Object.hasOwn验证“字段不存在”，不仅检查值为undefined。
本轮未改变API返回、角色过滤或任何数据访问权限；未为满足类型定义增加后端字段。

## 验收入口

- 普通 `npm run test:api`：没有专项DB时仍允许跳过。
- `npm --workspace @ai-video-qc/api run test:diagnostics-acceptance`：强制要求V11_DIAGNOSTICS_TEST_DATABASE_URL，缺少时非零退出。
- `npm run test:release-acceptance`：同时执行原Release测试与诊断HTTP测试，RELEASE_ACCEPTANCE_REQUIRED对两者生效。
- 所有诊断DB目标都经过既有assertIsolatedDatabase白名单检查，拒绝生产主机/端口/库名。
- 完整Release测试库与诊断库必须不同：至少host:port/database不同，不能因两套fixture相互污染导致伪结果。
- 实际验证过缺环境失败、普通跳过、非隔离目标失败与两套测试指向同库失败；不是只检查脚本文本。

完整Release下一阶段需要两个全新隔离数据库，以及RELEASE_TEST_MEDIA_PATH指向的合成素材；分别设置RELEASE_TEST_DATABASE_URL和V11_DIAGNOSTICS_TEST_DATABASE_URL，并设置QC_LOCAL_ACCEPTANCE=1、QC_SKIP_DOTENV=1。不能使用本轮已写fixture的数据库直接重跑空库验收。

## 空代表Run

既有聚合算法仅从本group中、sourceRunIds指定且status=succeeded的Run选择代表。本轮没有改变其计算或选择算法。
测试覆盖sourceRun不存在、失败及其他非成功状态；即使存在无关成功高分Run，也不得借用。
真实PostgreSQL中还建立其他已superseded revision的成功Run，验证将其ID作为来源不会跨revision读取证据。
无代表时observation/representativeRunId/suggestions为空，facts/factClaims/evidence为空数组；正式Decision总分保持原值。

## 前端竞态

原代码Promise.allSettled后无生命周期或序号检查，旧load可以写入较新的content/workflow/ratings，旧失败也可以清空新content。
最小修复：外层按videoId给内部面板设置React key；内部增加请求序号和mounted标记，只有最近一批、仍挂载的请求可以提交结果。
不改变请求集合、轮询间隔、Provider、Workflow或Gate。
浏览器人为延迟旧content/workflow/ratings，先完成新请求，再返回旧成功或旧503；确认新内容仍保留、旧Hold和旧数据评级不混入。
另用真实Next Link切换videoId后释放旧响应，确认新视频无旧分数和诊断；不是整页reload来规避竞态。

## 证据时间安全性：已核验与待授权方案

- content-schema.ts的证据字段要求finite、>=0；同时有值时end不能早于start。
- V11ContentService先Zod parse，再assertEvidenceWithinDuration；比较的是冻结input media manifest的durationSeconds。
- media-manifest.ts优先读取ffprobe时长，失败才用fallback；缺时长被列入input incomplete，当前执行也校验文件Hash。
- duration为null时现有函数跳过上界检查；本轮保留该历史兼容语义，没有发明时长。
- latest读取历史structuredOutput并不重新运行完整模型Schema或时长验证。前端只用toFixed输出范围，没有检查负数、顺序或总时长。
- 因此无法保证所有历史异常范围都不会显示；本轮未查询生产记录，不能声称已经发现具体坏记录，也不能声称已修复该历史风险。

建议另行确认后实施纯展示防护：对非数字/非finite/负数/倒序范围隐藏时间标记，保留证据描述并提示“时间范围未核验”；有可信冻结时长时再检查上界，缺时长不猜测。不clamp、不修写原JSON、不改评分、不新增跳转。
目前latest未向普通页面提供冻结时长，完整上界展示校验需要独立明确安全DTO来源；本轮不扩展该API。
