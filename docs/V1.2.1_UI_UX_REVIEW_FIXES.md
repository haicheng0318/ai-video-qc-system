## 根因与修复

| 问题 | 核验事实 | 本轮处理 |
| --- | --- | --- |
| 左下角 N 重叠 | 浏览器 DOM 明确属于 `nextjs-portal` 的 Next 开发指示器，不是登录用户头像；应用中不存在对应 avatar 组件 | 使用 Next 官方 `devIndicators: false` 关闭开发工具浮层，不以 CSS 隐藏账户或裁切业务内容 |
| 移动抽屉底部 | 原布局已有固定抽屉及滚动，但缺少显式底部安全区和子项防压缩约束 | 增加 overflow/overscroll、安全区 padding、品牌/导航/footer 不收缩；footer 保持普通流定位，保留主题、系统管理、退出操作 |
| 反面案例却 effective | V1.2.1 浏览器 fixture 对 excellent/negative 返回同一个 A/effective 示例 | 根据请求 type 返回独立的 D/invalid 反面样例；前端仅将真实 businessConclusion 映射为中文 |
| 版本标识 | `PRODUCT_VERSION` 只有 Web 展示调用和 shared 导出，没有协议/评分/数据库用途 | 常量更新 1.2.1，HTML title、登录、Shell、运行中心自动同步；既有浏览器版本断言同步 |
| 英文枚举 | 视频状态已有字典；历史综合结论可能原样显示 effective/low_effective/invalid，Hold 提示含技术英文 | 列表/卡片只做文字映射；未知视频状态显示“状态待确认”；不改变状态、查询或业务值 |
| reduced motion | globals 与 experience 各有一套规则 | 移除重复旧规则，保留 experience 中统一关闭 animation/transition/平滑滚动的规则 |

## 案例业务依据

- `apps/api/src/modules/v11/v11-ratings.service.ts` 的 `markCase()`：反面标记必须为 D 且 `final_invalid`；优秀标记必须为 S/A+/A 且 `final_effective`，并受 current workflow、Hold/Appeal、Shadow 和权限约束。
- `listCases()` 依据 `isExcellentCase` / `isNegativeCase` 查询；返回的 `businessConclusion` 直接来自正式综合 Decision。
- `comprehensive-matrix.ts` 将 D 映射为 invalid/final_invalid。
- 本次截图数据来源是 `apps/web/scripts/v121-browser-acceptance.mjs`，不是 seed 或生产记录。未访问生产数据，因此不声称核查了全部生产历史案例。
- 没有强制改写业务结论、审批、正式记录或 API 行为；未知业务结论仍保留原有安全显示兼容。
