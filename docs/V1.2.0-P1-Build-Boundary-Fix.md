## Root cause

`apps/api/tsconfig.json` includes `src/**/*.ts`, including tests, without a fixed rootDir. The static import at `apps/api/src/tests/v11-diagnostics-http.integration.spec.ts:12` brings in `apps/web/src/lib/v11-content-display.ts`. The inferred common source root expands to `apps`, producing `dist/api/src/main.js` instead of `dist/main.js`.

The actual pre-fix compiler file list contained 89 API test files, one Web source, and 242 API source files. All three expected flat entries were absent; all three nested entries existed. The original configuration already compiled tests; the new cross-layer dependency exposed this unstable boundary.

## Minimal fix

1. `apps/api/tsconfig.build.json`: extends the existing configuration, fixes rootDir to src, excludes src/tests, disables incremental emission for production builds.
2. `apps/api/package.json`: standard build explicitly selects that configuration and runs the output guard.
3. `apps/api/scripts/check-build-output.cjs`: requires flat app.module/main/worker entries and rejects nested API, Web and test output; does not execute application code.
4. `apps/api/src/tests/api-build-boundary.spec.ts`: four regression tests for production scope, retained development checks, build-script wiring and invalid artifacts.
5. This report.

The development tsconfig and test commands remain unchanged. Full Typecheck still checks cross-layer test sources and their Web dependency; tests are not hidden from the test runner. Production retains existing src/scripts and test-support dependencies used by HTTP acceptance commands.
