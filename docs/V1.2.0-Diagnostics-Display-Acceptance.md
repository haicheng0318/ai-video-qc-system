## API 契约

修复前成功分支：`{ shadowMode, group, dimensions, directorSummary }`。

修复前无 Decision：`{ shadowMode, group, diagnostics: null }`。

修复后统一：`{ shadowMode, group, diagnostics }`。

成功时 diagnostics 包含 dimensions/directorSummary；没有有效 Decision 时为 null。
本轮检索发现实际 Web 调用方仅评估面板读取嵌套 diagnostics；顶层依赖仅在 API 测试中。
因此未保留无实际调用方需要的顶层别名，测试与调用方一起更新。
如未来发现仓库外客户端依赖旧顶层字段，必须先评估兼容，不能假设其已升级。

共享契约在 API 通过 satisfies、聚合器返回类型、Web 状态类型及 Typecheck 共同约束。
HTTP 测试同时验证实际 JSON 外层键及 Prisma Decimal 序列化后的值，不以 TypeScript 断言替代运行时验证。

## 数据来源与展示语义

- 正式总分、等级仍来自 active pointer 选中的 V11EvaluationDecision。
- 八维得分仍来自该 Decision 的 adoptedDimensions 与原有后端权重。
- 观察、事实、证据、建议仍来自 sourceRunIds 中原聚合算法选中的代表成功 Run。
- 页面说明：诊断说明来自采纳结果对应的代表评估。
- 原有排序显示为“建议处理顺序”，不称为严重程度。
- 权重仍是 20/20/15/15/10/10/5/5；不改 anchor、等级阈值、计分或舍入。
- 历史记录缺少建议、证据或结构化观察时给出缺失提示，不用 Legacy 或其他 Run 伪造。
- Hold/Appeal、合规风险、未知输入、结果不稳定、C/D返修均不描述成已批准。
- Shadow/Pilot 保留实验标签；business latest 继续排除 pilotRun/independent。
- 存在评分不代表已通过后续关卡；未修改业务按钮权限或后端 Gate。

## Active pointer 读取修复

原查询在 current workflow 无 pointer 时按视频跨 revision 找最新 group，可能读到旧决议。
新增回归测试在修复前失败，明确复现未限定 workflowRevisionId。

现在：

1. 有 current workflow 时，所有 latest group 查询限定该 workflow ID。
2. 有 pointer 时，仅查匹配该 Decision 的 group，不以最新或最高分回退。
3. 无 pointer 时可展示当前进度，但响应中 Decision 为 null，诊断为 null。
4. 没有 current workflow 的历史视频保留原 business-group 回退。

这只是读取投影，未更新 pointer、历史 Decision、Run、Hold、Appeal 或业务状态。

### 隔离方式

- 新建 postgres:16-alpine 临时容器，数据库存储使用 tmpfs，不挂载已有 volume。
- 仅绑定 127.0.0.1:55443；仅允许 local-acceptance 白名单数据库 release_test。
- 测试使用专用无效登录 hash 的 fixture 用户及短时测试 Session，不复制真实用户或视频。
- 测试不启动 Worker；模型依赖为禁止调用的 fake；configureLocalAcceptance 清空模型/对象存储凭据。
- GET latest 使用真实 Prisma、权限服务、JWT/Session、Controller、Service 与 HTTP JSON。
- 同一 HTTP 响应传入生产使用的 Web 诊断组件做真实 React 渲染，验证八维与内容。
- 浏览器仅允许 loopback，请求拦截全部 API，其他 origin 被拒绝。

### 测试过程中失败及处理

- 修复前两项 API 回归失败，分别暴露嵌套契约与跨 revision 查询问题；修复后通过。
- 初次编译发现测试直接导入 TSX 与 API 编译设置不匹配；改为测试运行时加载实际 Web 组件，不改 API 编译配置。
- 浏览器状态断言最初错误限定在面板内，而摘要由 Portal 渲染在外部；修正定位，不改业务行为。
- 重跑发现上传跳转目标缺 GET 详情 fixture，返回空对象；补齐真实详情形状，不屏蔽 pageerror。
- 最终结果以修正后的实际重跑为准，不把上述失败隐藏成从未发生。
