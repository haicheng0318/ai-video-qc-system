# AI短视频质检评估系统 V1.0 完整改造开发方案

- 报告版本：V1.1（方案版）
- 更新日期：2026-09-07
- 当前状态：待确认开发
- 适用项目：AI短视频质检评估系统 V1.0

## 1. 改造目标

本次开发合并以下需求和已确认问题：

1. 缩小视频播放窗口，重构视频详情页布局。
2. 参照“视频需求数据看板”的视觉和交互规范统一质检系统前台，但不合并代码、数据库、服务或部署环境。
3. 新增独立管理员登录入口和管理员后台。
4. 管理员可以创建、停用、续期和管理访客账号，并控制上传与评估额度。
5. 建设视频任务、AI服务、COS、OSS、使用量、费用、日志与安全管理能力。
6. 修复点击触发内容评估后必须手动刷新才能看到结果的问题。

## 2. 当前系统基础与缺口

项目继续沿用 Next.js、NestJS、PostgreSQL、Prisma、JWT、腾讯 COS、阿里 OSS 和阿里云百炼千问。现有系统已经具备视频上传、内容评估、主管审核、投放数据、数据复盘、规则引擎、最终评定、负责人确认、看板和案例库。

已确认的本次主要缺口：

- 当前播放器没有合理的宽高约束。
- 视频详情页全部模块纵向展开，信息层级不清晰。
- 前台设计语言与视频需求数据看板不统一。
- 现有 `admin` 角色已存在，但没有完整管理员后台和账号管理接口。
- 没有独立 `visitor` 角色、账号有效期、额度和会话回收。
- 没有统一的评估任务管理中心和完整服务健康看板。
- 内容评估触发后只立即请求一次最新结果，缺少后续状态轮询。

## 3. 总体技术方案

| 模块 | 方案 |
| --- | --- |
| 前端 | 继续使用 Next.js 14 + React，拆分普通用户布局与管理员布局 |
| 后端 | 继续使用 NestJS，增加管理员、任务、监控和配额模块 |
| 数据库 | PostgreSQL + Prisma，使用向后兼容迁移 |
| 鉴权 | 保留 JWT 核心，增加安全 Cookie、会话表和强制失效能力 |
| 正式视频 | 腾讯 COS 私有存储和短时签名访问 |
| AI临时中转 | 阿里 OSS 私有 Bucket，限定前缀并在1天后清理 |
| AI服务 | 千问负责内容评估、数据复盘和最终建议，规则引擎仍为后端代码 |
| 部署 | 腾讯云轻量服务器 + Docker Compose + Nginx |
| 密钥 | 仅服务器环境变量，前端、数据库和日志均不得保存明文 |

## 4. 普通用户前台改造

### 4.1 全局布局

使用与视频需求数据看板一致的浅色设计语言：左侧导航、顶部页面标题、白色圆角卡片、渐变指标卡、统一状态标签、表格、筛选、分页、空状态和错误提示。只复用设计规则，不复制或合并看板代码。

普通用户导航：

- 工作台
- 视频列表
- 上传评估
- 数据看板
- 优秀案例
- 反面案例
- 基准配置（按权限显示）
- 返回功能入口

### 4.2 视频详情页

- 竖屏视频宽度控制在 360～420px，最大高度约 560px。
- 横屏视频最大宽度约 720px，保持原始宽高比。
- 使用 `object-fit: contain`，不拉伸、不裁切。
- 桌面端采用“左侧视频、右侧摘要”，移动端切换为上下布局。
- 首屏展示状态、三个等级、当前负责人、下一步动作和最近错误。
- 下方使用标签页：内容评估、主管初审、投放数据、数据复盘、规则判断、最终评定、操作记录。

## 5. 内容评估结果自动刷新专项修复

### 5.1 缺陷说明

当前点击“触发内容评估”后，前端等待触发接口返回并立即调用一次 `loadVideo()`。此时后台任务通常仍在执行，页面只能显示“评估中”；后端完成后没有新的请求，因此必须手动刷新页面才能看到结果。

### 5.2 修复方案

第一版采用与现有数据复盘、最终评定一致的有边界轮询机制：

1. 触发成功后立即将界面切换为“内容评估中”。
2. 每3秒读取一次最新内容评估和视频状态。
3. 状态变为 `succeeded`、`failed` 或视频进入下一个业务状态时自动停止。
4. 连续网络错误达到上限后停止轮询并给出“重新加载状态”按钮。
5. 达到最长等待时间后提示任务仍在后台执行，允许继续查询或由管理员检查。
6. 页面切换到后台时降低请求频率；回到页面后立即同步一次。
7. 离开页面、切换视频或组件卸载时清理定时器，避免重复请求。
8. 禁止评估中重复点击，避免创建并发任务。
9. 完成后自动刷新内容结果、视频状态、流程步骤和可用操作，不整页刷新。

### 5.3 后续增强

管理员任务中心完成后，可将轮询统一基于 `evaluation_jobs`。本阶段不强制引入 WebSocket/SSE，避免增加生产代理和断线重连复杂度；后续并发量明显上升时再升级为服务端事件推送。

### 5.4 验收标准

- 点击触发后无需手动刷新即可看到最终结果。
- 成功、失败、超时和网络中断均有清晰状态。
- 轮询在终态后停止，不产生持续请求。
- 快速重复点击不能产生重复运行任务。
- 切换页面后不会遗留定时器。
- 线上真实短视频完成评估后，页面自动更新内容等级和流程状态。

## 6. 独立管理员后台

### 6.1 页面入口

- 管理员登录：`/admin/login`
- 管理员首页：`/admin`
- 普通用户访问 `/admin/*` 时由前后端共同拒绝。
- 管理员后台使用独立侧边栏、页头和权限边界，并提供“返回业务系统”。

### 6.2 管理员导航

- 管理看板
- 账号管理
- 角色与权限
- 视频与评估任务
- AI服务管理
- 存储服务管理
- 使用量与费用
- 业务配置
- 操作日志
- 安全中心
- 系统设置

### 6.3 管理看板

展示用户总数、访客数、即将到期账号、今日上传、今日完成、运行中任务、失败任务、待人工处理、本月AI调用量；同时展示评估流程漏斗、成功率趋势、异常任务、服务健康状态和即将到期账号。

### 6.4 账号管理

支持创建单个或批量账号、创建访客和业务角色账号、设置有效期、上传额度和评估额度、启停账号、重置密码、强制退出、延长有效期、查看使用量和审计历史。已产生业务数据的用户只允许停用或归档，不物理删除。

### 6.5 访客权限

新增 `visitor` 角色。访客可以登录、修改密码、上传视频、查看自己的视频、触发自己的内容评估、查看自己的结果和剩余额度；不能查看他人数据、进行主管审核、填写正式投放数据、执行规则引擎或最终评定、访问全局看板、修改基准或进入管理员后台。

### 6.6 视频与评估任务

管理员可按视频、用户、状态、模型、时间搜索任务，查看历史结果和错误，回收超时任务、重新触发、标记人工处理。重试必须产生新记录，不能覆盖原始AI结果，并写入操作日志。

### 6.7 AI与存储服务

显示千问模型、配置状态、最近成功/失败、成功率、耗时、限流与解析错误；显示COS和OSS的区域、Bucket、上传、读取、签名、容量、生命周期和最近错误。密钥只显示“已配置/未配置”，不能在页面中回显。

### 6.8 使用量、配置、日志与安全

统计各AI环节调用量、成功率、耗时、用户额度、COS容量和OSS中转量；支持管理非敏感业务配置并保存版本；记录登录、账号、权限、任务、模型、基准、删除、人工调整和越权操作；安全中心展示失败登录、异常IP、有效会话、账号到期和越权事件。

## 7. 数据库改造

### 7.1 用户数据

`UserRole` 增加 `visitor`；`users` 增加首次改密、有效期、创建人、最近登录、密码修改时间、令牌版本和归档时间等字段。

### 7.2 新增表

- `user_quotas`：上传和评估额度。
- `user_sessions`：登录会话及强制失效。
- `evaluation_jobs`：内容评估、数据复盘和最终评定任务生命周期。
- `ai_usage_logs`：模型调用、耗时、计费量和错误分类。
- `service_health_checks`：数据库、AI、COS、OSS和服务健康历史。
- `system_settings`：只保存非敏感配置。

所有迁移保持旧数据可读，AI结果继续保留原始响应和历史版本。

## 8. 主要新增接口

- `/api/admin/auth/*`：管理员登录、身份和退出。
- `/api/admin/users/*`：账号、状态、密码、会话和额度管理。
- `/api/admin/dashboard/*`：指标、流程、趋势、告警和服务健康。
- `/api/admin/evaluation-jobs/*`：任务查询、回收、重试和人工处理。
- `/api/admin/ai-services/*`：AI配置状态和连通测试。
- `/api/admin/storage/*`：COS、OSS状态和连通测试。
- `/api/admin/usage`：使用量与费用统计。
- `/api/admin/operation-logs`：审计日志。
- `/api/admin/security/events`：安全事件。
- `/api/admin/settings`：非敏感系统设置。

## 9. 开发顺序

1. 建立测试基线、备份数据库并记录当前生产版本。
2. 优先修复内容评估自动刷新和播放器布局问题。
3. 完成数据库迁移、访客角色、会话与额度。
4. 完成管理员鉴权、账号管理和后端权限测试。
5. 完成任务中心、AI/COS/OSS监控和使用量统计。
6. 完成管理员看板、日志、安全中心和配置页。
7. 统一普通用户前台UI和视频详情页交互。
8. 完成单元、集成、浏览器端到端和生产冒烟测试。
9. 发布到现有独立腾讯云轻量服务器，验证后切换正式版本。

## 10. 测试与验收

测试覆盖登录、管理员越权、访客隔离、账号到期、额度耗尽、会话回收、视频上传和播放、内容评估自动刷新、AI失败/超时、任务回收、COS/OSS、数据复盘、规则引擎、最终评定、看板统计和操作日志。

自动化测试默认使用模拟AI响应，不消耗真实额度；生产部署后使用一个小视频执行真实全链路冒烟测试。

## 11. 交付和回滚

交付内容包括统一后的前台、独立管理员后台、访客账号管理、任务中心、服务监控、使用量、配置、日志、安全中心、数据库迁移、接口和测试报告、缺陷统计表、部署版本与访问地址。

部署前保留数据库备份和上一版Docker镜像；如出现问题，切回上一镜像。数据库迁移优先采用向后兼容方式，不删除旧字段、AI历史结果和操作日志。

## 12. 预计工作量

完整范围预计7～9个开发工作日。其中内容评估自动刷新作为P0缺陷优先完成，不等待管理员后台全部完成后才修复。云平台身份验证、新密钥、域名或证书操作如有需要，再由用户介入。
