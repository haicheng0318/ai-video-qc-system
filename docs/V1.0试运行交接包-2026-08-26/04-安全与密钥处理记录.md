# 安全与密钥处理记录

## 1. 已发生事项

2026-08-26 的沟通中曾出现以下敏感信息：

- 阿里云百炼 API Key。
- 阿里云 RAM 登录名称。
- OSS AccessKey ID。
- OSS AccessKey Secret。
- RAM 登录密码栏位（沟通中未见可用密码原文）。

交接包中的上述内容均已脱敏，不包含可用凭据。

## 2. 必做安全操作

1. 在百炼控制台轮换已经出现在对话中的 API Key。
2. 在 RAM 控制台禁用并删除已暴露的 OSS AccessKey，创建新 AccessKey。
3. 新凭据只填写到本地 `.env`，不再发送到任何对话框。
4. 轮换后重启 API，使用小样片验证一次，然后再验证 60 MB 业务视频。
5. 确认日志中不包含完整 Key、AccessKey 或带签名查询参数的 OSS URL。

## 3. OSS 最小权限建议

测试阶段曾为 RAM 用户授予 `AliyunOSSFullAccess`。试运行前建议收紧为：

- Bucket：仅 `pjxt`。
- 对象前缀：仅 `ai-video-qc/content-review/*`。
- 允许操作：`oss:PutObject`、`oss:GetObject`、`oss:DeleteObject`。
- 不授予 Bucket 删除、ACL 修改、公开读、全局 Bucket 列表等无关权限。

## 4. 安全基线

- `.env` 必须被 Git 忽略。
- 前端不能出现任何模型密钥。
- 后端只在运行时读取环境变量。
- OSS Bucket 必须保持私有并开启阻止公共访问。
- OSS 签名 URL 必须使用短 TTL，不得持久化到前端或业务数据库。
- OSS 临时对象必须在成功、模型失败、解析失败和超时各路径下清理。
